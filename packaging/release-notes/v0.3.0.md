## Switchyard is now Relayweft, and `sy` is now `rw`

This is the first release under the new name. The repository moved to
[Sparkz400/Relayweft](https://github.com/Sparkz400/Relayweft); the old URLs
redirect. The binaries are now `rw-<os>-<arch>` (`rw-windows-amd64.exe`, ...),
and there are no `sy-*` copies. **`sy update` cannot install this release:**
it stops with "release v0.3.0 has no sy-… asset" and leaves `sy` as it was.

### Upgrading from `sy` (v0.1.0, v0.2.0): reinstall once

1. **Install `rw`** the way you installed `sy`:
   - **Downloaded binary:** download `rw-windows-amd64.exe` (or `rw-<os>-<arch>`) from this release, rename it to `rw.exe` (`rw`), and put it where `sy` was. Later updates work again with `rw update`.
   - **Scoop:** `scoop uninstall sy`, then `scoop install https://raw.githubusercontent.com/sparkz400/relayweft/main/packaging/scoop/rw.json`.
   - **Homebrew** (tap added as Switchyard): `brew update && brew upgrade` should move the `switchyard` formula to `relayweft` (the tap has a `formula_renames.json`). If it doesn't: `brew uninstall switchyard && brew untap sparkz400/switchyard`, then `brew tap sparkz400/relayweft https://github.com/Sparkz400/Relayweft && brew install relayweft`.
   - **Built from source:** `go install github.com/sparkz400/relayweft/cmd/rw@v0.3.0`.
2. **Run `rw` once** (any command, for example `rw doctor`). On its first start, rw copies your Switchyard folder (`%APPDATA%\switchyard` on Windows, `~/.config/switchyard` on Linux, `~/Library/Application Support/switchyard` on macOS) to `relayweft`. This brings over your config, task history, session logs, health and debug logs (`rw health` keeps your streak), learned routes, reports and trust list. rw says so in one line. The old folder stays as it is. The copy happens only once: anything `sy` writes after that is not copied.
3. **Rename your repos' config files:** `.switchyard.yaml` becomes `.relayweft.yaml`, and `./switchyard.yaml` becomes `./relayweft.yaml`. rw does not read the old names. It tells you when it finds one. Trust carries over to a renamed file whose content has not changed; otherwise run `rw trust` again.
4. **Remove `sy`** once `rw` works: delete `sy.exe` (or `scoop uninstall sy`, `brew uninstall switchyard`).

### Other renamed things to check

- **Environment variables:** `SY_*` became `RW_*`, for example the hook variables `RW_TASK`, `RW_FILES` and `RW_STATUS`, and `RW_NO_SETUP`. Hooks that read `$SY_…` need the new names.
- **Branches:** task branches are now `rw/…`. Old `sy/…` branches and `refs/switchyard/…` snapshots are left alone, so `rw undo` and `rw clean` do not see them. Delete them by hand when you no longer need them.
- **Old worktree pool:** the worktree pool, MCP cache and sandbox cache under `%LOCALAPPDATA%\switchyard` (`~/.cache/switchyard`, `~/Library/Caches/switchyard`) are not used any more. Once you no longer need to resume tasks started with `sy`, delete that folder and run `git worktree prune` in your repos. rw builds its own pool.
- **Scheduled runs:** Windows tasks named "Switchyard HH:MM" (cron lines that run `sy`) still start `sy`. Re-create them with `rw schedule`, then delete the old ones.
- **Sandbox image:** the sandbox image is now `relayweft-sandbox`, and rw builds it again.
- **CI:**
  - The GitHub Action is now `Sparkz400/Relayweft@v0.3.0`, and the documented issue label is `rw`.
  - The GitLab template uses `RW_*` variables and the schedule variable `RELAYWEFT=1`.
  - The Forgejo/Gitea template uses `RW_*` variables and the secret `RELAYWEFT_TOKEN` (was `SWITCHYARD_TOKEN`).
  - Workflows pinned to `@v0.2.0` keep working with `sy`.
- **Editors:** the VS Code extension is `sparkz400.relayweft`, with settings `relayweft.*`. The JetBrains plugin is `io.github.sparkz400.relayweft`. Settings of the old ids do not carry over.
- **Unchanged:** comments `sy` posted on pull requests, team-queue claims and stats exports from `sy` machines still count.
